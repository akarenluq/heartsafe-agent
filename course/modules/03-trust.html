Can we trust this reading?

How HeartSafe checks every number before a nurse is asked to act on it.

The bank teller's habit

A good bank teller does not cash a cheque just because it was handed over. They check the signature, the date, whether the amount in words matches the digits. Only then does the money move.

HeartSafe treats every platform alert the same way: first check the evidence, then decide who should act.

Step 1: the platform's own alarm

HeartSafe first recreates the platform's alert. In monitoring.py, these lines decide when a day becomes critical (level 2) rather than caution (level 1).

CODE 
        if sbp[i] < lim["sbp_low"] or sbp[i] > lim["sbp_high"]:            crit.append(f"systolic BP {sbp[i]:.0f}")        if not np.isnan(dbp[i]) and dbp[i] > lim["dbp_high"]:            crit.append(f"diastolic BP {dbp[i]:.0f}")        if hr[i] < lim["hr_low"] or hr[i] > lim["hr_high"]:            crit.append(f"heart rate {hr[i]:.0f}")        breathless = sym["sob"][i] or sym["orthopnea"][i] or sym["pnd"][i]        if crit or (breathless and weight_rule):            levels[i] = 2            f.extend(c for c in crit if c not in f)        elif f:            levels[i] = 1

Systolic blood pressure below or above this patient's limits…

…is a critical sign.

So is a diastolic pressure above the limit (if one was measured)…

…

…and a heart rate outside the patient's limits.

…

"Breathless" means short of breath, breathless lying flat, or waking up breathless.

Any critical sign, or breathless plus a weight-gain rule…

…makes the day level 2 (critical)…

…and the critical reasons are added to the list of rules that fired.

Otherwise, if any milder rule fired…

…the day is level 1 (caution).

🩺
Per-patient limits

lim holds this patient's own limits. A clinician can set them at enrollment, so a patient whose usual BP is 88 is not flagged every single day.

Step 2: is the number even real?

Two common home-monitoring mistakes: weight typed in pounds instead of kilograms, and a new scale that reads 2 kg heavier. reliability.py catches both by comparing today with the last three readings.

CODE 
    if not np.isnan(med_w):        ratio = w / med_w        if r["unit_error_ratio"][0] <= ratio <= r["unit_error_ratio"][1]:            flags.append("unit_error")            notes.append(f"weight {today['weight_kg']:.1f} is about 2.2x the recent {med_w:.1f} kg (entered in lb?)")        else:            step = w - med_w            hr_stable = np.isnan(med_hr) or abs(hr - med_hr) <= r["hr_stable_bpm"]            if abs(step) >= r["step_change_kg"] and not symptoms and hr_stable:                flags.append("step_change")                notes.append(f"weight jumped {step:+.1f} kg overnight with no symptoms and stable heart rate (new scale?)")
PLAIN ENGLISH

Only if we have a recent typical weight to compare with:

Divide today's weight by that typical weight.

About 2.2 times heavier? (1 kg is 2.2 lb.)

Then flag it as a unit error…

…and write a note a nurse can read.

Otherwise:

Measure the overnight jump in kilograms.

Is the heart rate about the same as usual?

A big jump with no symptoms and a steady heart rate…

…looks like a new scale, not fluid build-up…

…so flag it and explain why.

💡
Flags plus notes

Every check returns two things: a short machine flag that drives the decision, and a sentence for humans. Ask AI tools for both whenever a system makes a call that a person must later understand.

Step 4: the ECG lab's verdict

The ECG model is a group of five neural networks (an ensemble) trained on hospital ECGs. For each recording it reports quality, uncertainty and a shift score, then makes one of three calls:

CODE 
    def decide(self, q_flags, unc, shift, scale):        flags = list(q_flags)        if unc > self.thr["uncertainty"] * scale:            flags.append("high_uncertainty")        if shift > 1:            flags.append("device_shift")        if q_flags:            return flags, "repeat"        return flags, ("escalate" if flags else "accept")
PLAIN ENGLISH

Decide using the quality problems, uncertainty, shift score and any safeguard adjustment.

Start with the quality problems found so far.

If the model is more uncertain than its calibrated limit…

…flag "high uncertainty".

If the recording is beyond the shift limit (scores are scaled so 1 = the limit)…

…flag "device shift".

Any quality problem?

Then ask the patient to record again: repeat.

Otherwise any flag means a clinician should look: escalate. No flags: accept.

The MRI lab and the unfamiliar scanner

⚖️
Every threshold is a trade-off

A stricter check catches more faults but buries reviewers in false alarms, and an overloaded reviewer misses things too. The thresholds here were set from clean data only, then the trade-off was measured and written down.
