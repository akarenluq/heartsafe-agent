The outside world

The services HeartSafe depends on, and why the demo keeps working when one of them is missing.

Everything that is not our code

A useful habit: list every outside service a project touches, and ask "what happens if it is slow, costs money, or disappears?" For HeartSafe:

🖥️
SDRE cluster (University of Alberta)

Powerful GPU machines where the ECG and MRI models are trained. Used once, offline. Not needed for the demo.

📚
Public datasets

PTB-XL (hospital ECGs), PhysioNet/CinC 2017 (home AliveCor ECGs), M&Ms (MRI from four scanner makes). De-identified; never committed to git.

✨
Claude API

Writes the wording of a case review on request. Optional: without a key, a template writes it.

🗄️
SQLite + Streamlit

A database that is just a file, and a Python library that turns a script into a web dashboard. Both run on the laptop.

Training far away, using results locally

Training happens on a shared cluster run by Slurm. Each job starts with a list of what it needs, and asking for far more than it uses lowers your team's priority next time.

Cache the expensive part

The models never run live during the demo: their saved results do. Separating "slow, expensive, done once" from "fast, done every time" is one of the most useful design moves you can ask an AI tool for.

Claude as a careful assistant

When a nurse clicks "Explain with AI agent", orchestrator.py gives Claude a case and a set of read-only tools. Claude gathers the facts, then hands in the review through a tool with a fixed shape.

Allow at most 8 rounds of back-and-forth, so it can never loop forever.

Send the conversation so far to Claude, through the API…

…with the instructions, the tools, and medium thinking effort.

(A note on the next line.)

If Claude declines for safety reasons, the service retries on a fallback model.

If it still declined…

…treat that as a failure.

Collect the tools Claude asked to use this round.

If it asked for none…

…it stopped without handing in a review: also a failure.

Otherwise keep its reply in the conversation and run the tools it asked for.

Always have a plan B

The whole loop is wrapped so that any problem (no internet, no key, a refusal, a malformed answer) gives the nurse the same review written by the template. The flow of care never depends on the language model. (So far this loop has been tested with a stand-in client, not yet against the live API.)
